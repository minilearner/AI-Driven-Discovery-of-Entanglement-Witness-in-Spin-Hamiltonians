# Data access and scientific identity

The HDF5 datasets were recovered locally from the private research archive.
They are **not bundled with this code repository** and have not been uploaded.
Their small compressed file sizes do not imply cheap
generation: several benchmarks require thermal purification, DMRG, or many
independent PPT/CCNR certificate calculations.

The exact current hashes, label counts, source-path mapping, and verification
flags are in `reports/phase3_benchmarks/benchmark_reproduction.json`. The five
server-preserved HDF5 files matched their archived SHA-256 values. The matched
XY file has no server-preservation entry; its own generation metadata and
current SHA-256 are retained. The private archive also has older 312-row OOD
files under `data/ood_hamiltonian_n16_v1/`. They are **not** interchangeable
with the current adaptive Gibbs paper benchmark, even though they share
Hamiltonian family names. Their saved `model/ensemble_score` fields refer to a
historical model and were not used for Phase 3 inference.

## Recompute benchmark predictions

Place these HDF5 files at the relative paths above under a local archive root,
then run from the repository root:

```bash
python scripts/reproduce_benchmarks.py --archive-root /path/to/local/archive
```

The script checks the server-preserved hashes when the preservation manifests
are available at `reports/remote_preservation_20261106/` under that archive
root. It loads the final Dv1-only ensemble once, keeps the p=0.5 threshold,
excludes unknown rows from metrics, and emits six per-row score CSV files and
one comparison JSON. It does not use the enhanced R2Support model for the
main zero-shot transfer table.

## Regeneration sources and limitations

- The base OOD Hamiltonian samples are generated by
  `scripts/run_ood_hamiltonian_n16.py`.
- The later adaptive Gibbs extensions are generated by
  `scripts/generate_adaptive_gibbs_ood.py`. Its `generate` stage requires the
  prerequisite 312-row base HDF5 files through `--base-root` and a passing
  numerical `regression` stage. XXZ and random-local finite-temperature
  generation use TeNPy purification, which is an optional heavy dependency;
  J1-J2 uses the recorded thermal numerical route. The source is retained,
  but a full regeneration has not been rerun for this public release.
- N=32 matched XY uses `scripts/generate_xy_n32_size_transfer.py` and is
  linked to a particular source N=16 sample set by the dataset metadata.
- The independent N=32 synthetic states use
  `scripts/generate_dpi_n32_general.py`; General-Sep uses
  `scripts/generate_general_separable_ood.py`.
- The 50,000-row Dv1 primary training dataset is kept locally at
  `data/n16_production_v1/dataset.h5`; the final model uses its fixed
  35,000/7,500/7,500 train/validation/test split. A 128-train/64-validation
  smoke run succeeded, but it is **not** a full final-model retraining.

The large benchmark data and full training caches can be deposited later in a
separately versioned archive using the hashes above. This repository includes
the final model weights, compact figure sources, and per-row benchmark scores,
but not the underlying complete HDF5 states.
